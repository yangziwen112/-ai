# 校园 Agent 编排 Skill

把 Agent 当作可观测的业务工作流，而不是一个自由聊天的黑箱。

## 适用场景

- 用户询问校园通知、考试、竞赛、就业、时间或平台功能；
- 用户询问“你忙吗”“你的边界在哪里”“你能做什么”等轻量对话；
- 需要处理权限、隐私、证据不足、工具失败或模型超时；
- 修改 LangGraph/LangChain 工作流、Agent 节点和评测用例。

## 编排规则

1. 先做本地情境识别和安全检查，再做意图路由；闲聊、能力边界、当前时间和安全拒答优先走本地快速路径，不调用大模型和联网工具。
2. 路由节点只决定任务和允许的工具，不能把数据库原始对象交给模型。
3. 工具必须返回最小公开投影，并标明 `available`、来源和失败原因。
4. 互不依赖的工具并行执行；单个工具失败不得拖垮其他结果。
5. 回答使用“结论—依据—下一步”；涉及日期、政策、地点和报名条件时没有证据就明确说明不确定。
6. 审核最多允许一次修订；仍不通过时安全降级，不猜测、不伪造、不泄露内部字段。
7. 每次运行记录 `traceId`、路由、工具、证据数量、审核分数、重试次数和延迟，不记录隐藏思维链。

## 轻量对话处理

以下请求必须快速本地响应：

- “你忙吗”“在吗”“方便吗” → 简短确认在线并提示可处理的校园任务；
- “你是谁” → 说明民大通助手的实际能力；
- “你的边界在哪里”“你能做什么” → 说明公开资讯、时间、竞赛、考试和平台帮助范围，同时说明不能读取密码、私信、身份证和管理员内部数据；
- “谢谢”“晚安” → 简短礼貌回应。

不要因为一句闲聊启动 RAG、联网搜索或数据库查询。

## 评测要求

每新增一个路由，至少补充：正常输入、模糊输入、权限输入、工具失败和超时降级用例。重点检查：

- 闲聊响应不依赖模型配置；
- 边界回答不暴露系统提示或内部工具；
- 精确日期必须有证据；
- 失败时用户能知道下一步怎么做；
- 游客、普通用户和管理员的数据投影不同。
