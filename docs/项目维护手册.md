# 民大通项目维护手册

本文是项目当前唯一的综合维护说明。旧版快速开始、阶段性修复总结、标签视觉说明、图片测试说明、用户绑定方案和重复部署指南已经合并到这里，不再作为独立文档维护。

## 1. 产品边界

“民大通”是校园聚合信息平台，不是单一的教资应用。平台包含：

- 官方校园资讯：通知、竞赛、讲座、就业、考试考证、文体、志愿和校园活动。
- 个性化服务：订阅、收藏、浏览历史。
- 校园动态：第二个 Tab 聚合展示精选官方资讯、二手闲置与学生互动；二手内容使用独立 `market` 分类并要求实物图片。
- AI 助手：面向公开校园资讯的检索增强问答。
- AI 助手支持上传图片；图片会先上传到云存储，再由视觉模型分析，图片不会直接保存为本地临时路径。
- 管理中心：人工发布、资讯管理、自动采集和数据表初始化。

游客可浏览公开资讯与公开帖子，并体验 3 次 AI。收藏、订阅、发布、评论、私信和个人记录必须登录。

## 3. 本地运行

1. 使用微信开发者工具打开项目根目录。
2. 确认 `project.config.json` 的 `cloudfunctionRoot` 为 `cloudfunctions/`。
3. 确认 `app.js` 中的云环境 ID 与云开发控制台一致。
4. 重新编译，分别验证首页、校园动态、AI、消息和个人中心。

当前联调版本会自动使用 `admin001`。正式发布前必须同时关闭：

```text
utils/debug-config.js
  autoAdminLogin.enabled = false

cloudfunctions/api/index.js
  DEBUG_ADMIN_LOGIN_ENABLED = false
```

同时删除或关闭云端 `ENABLE_DEBUG_ADMIN` 环境变量。只关闭前端开关不够，后端开关也必须关闭。

## 4. 云函数部署

推荐顺序：

1. `rag`
2. `crawler`
3. `api`

在微信开发者工具中右键整个云函数目录，选择“上传并部署：云端安装依赖”。不要只上传 `index.js`。`rag` 使用 Node.js 18 或 20，超时 60 秒，内存建议 512 MB。

环境变量：

| 云函数 | 必填变量 | 说明 |
| --- | --- | --- |
| `rag` | `DEEPSEEK_API_KEY` | 文本/视觉模型 API 密钥 |
| `rag` | `RAG_INTERNAL_TOKEN` | API 调用 RAG 的内部密码 |
| `rag` | `DEEPSEEK_VISION_MODEL` | 可选；支持图片输入的模型名，未配置时沿用 `DEEPSEEK_MODEL` |
| `api` | `RAG_INTERNAL_TOKEN` | 必须与 `rag` 完全一致 |
| `api` | `CRAWLER_INTERNAL_TOKEN` | API 调用采集器的内部密码 |
| `crawler` | `CRAWLER_INTERNAL_TOKEN` | 必须与 `api` 完全一致 |

可选变量包括 `DEEPSEEK_MODEL`、`DEEPSEEK_API_HOST`、`DEEPSEEK_TIMEOUT`、`CRAWLER_SOURCES_JSON`、`CRAWLER_MAX_ITEMS` 和 `CRAWLER_TIMEOUT`。

内部 Token 不是 DeepSeek 密钥。它应为单独生成的随机字符串，并且不得写进代码或文档。

## 5. RAG 版本过旧排错

前端出现以下错误：

```text
RAG_DEPLOYMENT_OUTDATED
```

表示 `api` 收到的 `rag` 响应不符合当前协议，或者云端部署版本与本地代码不一致。当前要求：

```text
protocolVersion: star-rag-v2
deploymentVersion: star-langgraph-20260813-v2
```

处理步骤：

1. 确认云开发工具当前选中的环境与 `app.js` 环境 ID 一致。
2. 删除云端旧 `rag` 的错误部署版本时要谨慎；通常直接全量覆盖部署即可。
3. 右键 `cloudfunctions/rag`，选择“上传并部署：云端安装依赖”。
4. 确认运行时为 Node.js 18 或 20，并配置 `DEEPSEEK_API_KEY`、`RAG_INTERNAL_TOKEN`。
5. 再全量部署 `cloudfunctions/api`，并配置同一个 `RAG_INTERNAL_TOKEN`。
6. 重启本地云函数调试进程。云端环境变量不会自动进入本地调试进程。

健康检查输入：

```json
{
  "action": "health",
  "internalToken": "实际的新Token"
}
```

成功响应必须包含：

```json
{
  "code": 200,
  "data": {
    "protocolVersion": "star-rag-v2",
    "deploymentVersion": "star-langgraph-20260813-v2"
  }
}
```

常见错误：

- `RAG_INTERNAL_TOKEN_MISSING`：云函数环境变量未配置。
- `RAG_INTERNAL_TOKEN_REQUIRED`：测试请求未传 Token。
- `RAG_INTERNAL_ACCESS_DENIED`：两端 Token 不一致。
- `RAG_FUNCTION_EXECUTE_FAIL`：检查运行时、依赖安装、入口加载和云端日志。
- `ReadableStream is not defined`：部署了旧依赖或使用了不兼容的本地运行时；应全量部署当前 `rag`。

如果日志出现 `RAG_INTERNAL_ACCESS_DENIED`，按以下顺序处理：

1. 在微信云开发控制台确认当前项目选中的环境与 `app.js` 的 `envId` 完全一致。
2. 打开云函数 `api` 的环境变量，设置 `RAG_INTERNAL_TOKEN` 为同一随机字符串。
3. 打开云函数 `rag` 的环境变量，设置完全相同的 `RAG_INTERNAL_TOKEN`（不要多空格、引号或换行）。
4. 分别选择“上传并部署：云端安装依赖”，先部署 `rag`，再部署 `api`。
5. 重启开发者工具的本地云函数调试，再调用管理员页面的 RAG 健康检查。

代码只打印 Token 长度和不可逆的短指纹，不会输出密钥原文；两个函数日志中的指纹必须一致。

## 6. 数据与接口

主要集合：

| 集合 | 用途 |
| --- | --- |
| `users` | 账号、角色、头像和隐私设置 |
| `contents` | 官方及管理员发布的标准化资讯 |
| `sources` / `tags` | 来源与标签元数据 |
| `subscriptions` | 用户订阅标签和来源 |
| `favorites` / `history` | 收藏与浏览历史 |
| `campus_posts` / `campus_comments` / `campus_likes` | 校园墙内容与互动 |
| `messages` / `friend_requests` / `friends` | 私信与好友关系 |
| `ai_messages` / `ai_usage` / `ai_runs` | AI 历史、游客额度和运行审计 |
| `crawl_logs` | 采集任务记录 |

所有小程序业务请求统一经过 `cloudfunctions/api`。前端不能直接调用 `rag` 或 `crawler`，否则会绕过游客额度或管理员权限。

公开仓库不提供内部接口清单和鉴权排错细节。AI 工作流见 [ai_multi_agent_workflow.md](ai_multi_agent_workflow.md)，采集器见 [crawler_integration.md](crawler_integration.md)。

## 7. 主要业务验收

### 公开内容

- 游客可打开首页、筛选、搜索和查看详情。
- 列表与详情只返回 `status=published` 的内容。
- 来源、时间、分类和原文链接一致。
- 采集内容保留权威来源并存入 `contents`，可在“校园动态”聚合流展示，但绝不写入或伪装成 `campus_posts` 学生帖子。

### 登录与个性化

- 游客触发个性化操作时出现友好登录引导。
- AI 聊天支持文字和图片；图片最多 4 张，发送前必须完成云存储上传。
- 登录后订阅、收藏和历史按账号隔离。
- 退出账号后清理账号相关本地缓存。
- 管理入口只对真实管理员显示。

### 校园动态与消息

- 发布图片必须先上传云存储，不能保存临时路径。
- 列表和详情接口必须过滤 `127.0.0.1`、`__tmp__`、`wxfile://` 等失效临时图片地址。
- 页面回到前台超过 30 秒自动刷新，可见期间每 60 秒同步一次；发布成功后立即强制刷新。
- 匿名内容在任何公开响应中都不能暴露作者 ID。
- 帖子和评论应经过内容安全检查，并提供举报、下架和删除闭环。
- 好友申请必须有查看、接受和拒绝入口。
- 私信列表返回页面后刷新，收发方向和未读数正确。

### AI

- 游客只有成功收到回答才消耗次数，最多 3 次。
- 涉及日期、政策、报名和考试安排时必须有平台证据。
- `reviewStatus=approved` 才显示“已审核”，降级回答不能显示同样徽章。
- 模型失败不保存伪造的成功回复，不污染历史。

## 8. 当前已知问题与解决方向

以下问题来自 2026-08 静态复核，尚未全部完成：

1. 调试管理员后门仍开启。正式发布前按第 3 节关闭前后端开关。
2. 普通注册没有学校身份校验。接入学号认证、统一身份认证或人工审核，不应无条件显示“已认证”。
3. 密码重置仅使用身份证后四位。增加短信/邮箱验证码、限流和安全审计。
4. 首页“推荐”尚未真正消费用户订阅。`feed/recommend` 应读取 `subscriptions` 并进行可解释排序。
5. 订阅页只实现标签，来源订阅未形成 UI 和推荐闭环。
6. 校园墙缺少内容审核、举报、作者删除和管理员下架。
7. 匿名评论前端可选，但后端仍固定为非匿名；需统一请求和存储协议。
8. 拉黑仅存本地且服务端不筛选；应建立账号级黑名单集合并在列表、搜索、评论、私信中生效。
9. 好友申请后端接口存在，但前端缺少处理页面；用户详情页路由也未实现。
10. 私信消息、收藏和历史存在排序、分页、统计和错误吞没问题，应在接口层返回真实错误与稳定顺序。
11. 采集器串行抓取且结果直接发布。应增加受控并发、文章级失败状态、待审核队列与重试机制。
12. AI 当前只检索 `contents`，没有实现文档中提到的外部网络检索；产品文案应与实际能力一致。

建议按安全与业务闭环优先：认证和权限 > 内容审核 > 订阅推荐 > 社交闭环 > 指标与性能 > 视觉统一。

## 9. 历史改动摘要

旧文档记录的有效改动已归纳如下：

- 管理员资讯支持发布、编辑、删除、图片上传、标签和来源选择。
- 卡片与详情页完成基础排版，支持收藏、分享、原文和图片预览。
- 收藏与历史迁移到云数据库，并提供单条删除和清空操作。
- 登录用户的数据通过用户 ID 隔离，游客仅访问公开能力。
- AI 已建立 LangChain 基础节点与 LangGraph STAR 编排。
- 采集器已支持多来源发现、正文抽取、分类、时间抽取、去重与日志。

历史文档中的示例账号、性能倍数、已完成声明和旧页面路径不再作为当前事实；验收必须以现有代码、云端配置和实际测试为准。
