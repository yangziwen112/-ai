# 从校园资讯到 AI 助手：我的个人小程序实践

> 以中央民族大学为真实校园场景，把散落在学校官网、学院通知、竞赛平台、考试考证页面和校园社区里的碎片化信息，汇聚成一个能持续更新、按需理解的校园助手。

## 产品定位

民大通面向中央民族大学学生，解决校园信息分散在学校官网、职能部门、学院、就业平台和校外权威网站中的问题。平台统一采集、分类和展示可信资讯，并提供个性化订阅、校园社区、消息与 AI 查询能力。

教资只是“考试考证”分类中的一个业务，不是平台主线。

## 为什么要做它

校园里最难解决的问题，往往不是“没有信息”，而是“信息无法在需要的时候被找到”。一条重要通知可能藏在学院网站的二级栏目里，一场竞赛可能只在群聊中转发一次，一项考试安排又可能出现在完全不同的官方平台。学生真正缺少的不是更多链接，而是一个能够判断来源、理解时间、提炼行动并持续更新的校园入口。

民大通从一个学生的真实使用痛点出发：把“到处翻、反复问、害怕错过”变成“集中看、直接问、知道下一步怎么做”。

## 项目的创新性

### 1. 从信息聚合升级为校园信息基础设施

传统资讯小程序只是把网页搬到卡片里；民大通进一步保存来源、发布时间、截止时间、地点、适用人群和行动项，让一条资讯变成可以检索、排序、提醒和追踪的结构化信息。

### 2. AI 不只回答问题，还负责理解校园语境

AI 助手不是套在页面上的通用聊天框。它会先识别用户是在查通知、问时间、找竞赛、处理二手书，还是需要解释一张图片，再选择对应的数据和工具；回答前还会检查时效、来源、权限和表达长度。

### 3. 建立“官方资讯”和“学生生活”的双层空间

官方内容强调可信、可追溯和时间准确；校园墙强调真实、轻量和互动。两类内容在产品中相互连接，但数据边界清晰，避免把学生发言误当成学校通知，也避免让官方信息淹没在普通帖子里。

### 4. 把碎片化内容转成可执行的下一步

资讯不再只展示摘要，而是尽量回答四个问题：这件事与谁有关、什么时候截止、在哪里办理、用户下一步该做什么。这样 AI 的价值从“生成一段话”转向“帮助用户完成一次校园行动”。

### 5. 用可复用 Skill 让个人项目持续成长

UI 规范、AI 工作流、时间读取、真实采集、内容审核、二手发布和视频内容处理都被整理成可复用 Skill。项目不依赖某一个页面或某一个模型，未来可以替换数据源、模型和部署环境，仍然保留统一的产品逻辑。

### 6. 个性化来自校园生活，而不是泛化推荐

平台可以逐步理解用户关注的学院、校区、考试、竞赛和时间偏好，但只使用必要数据，并通过公开投影和权限控制限制 AI 可见范围。个性化的目标不是让用户沉迷，而是让重要信息更早、更准确地到达。

## 这个项目的个人特色

- 以中央民族大学真实校园场景为设计起点，而不是抽象的“校园管理系统”。
- 教资只是考试考证中的一个业务，平台同时覆盖竞赛、讲座、就业、志愿、校园活动、二手书和学生交流。
- AI 回复追求短、准、能行动，避免“看起来很聪明但无法使用”的长篇套话。
- 管理员采集器按来源和业务拆分，允许单独更新教资、民大主页、竞赛和学院资讯。
- 不用虚构活动、旧年份和假链接填充页面；采集失败就明确显示失败，真实内容优先于页面热闹。

## 从一个小程序走向校园智能入口

当前版本解决的是“找到并理解信息”；下一阶段将继续解决“提前提醒、协同办理和形成个人校园记忆”。详细路线见 [创新方向与未来路线图](docs/innovation-and-roadmap.md)。

## 业务范围

官方资讯统一归入以下分类：

- 通知公告
- 竞赛实践
- 讲座学术
- 就业招聘
- 考试考证
- 文体活动
- 志愿服务
- 校园活动

首页公开展示官方资讯，并提供分类筛选、关键词搜索、近期时间节点和权威来源标识。校园墙承载学生交流内容，与官方资讯库相互独立。

## 用户与权限

### 游客

- 可浏览、搜索公开校园资讯
- 可浏览校园墙公开帖子
- 可体验最多 3 次 AI 对话
- 点击收藏、订阅、发布、评论、私信、个人记录等功能时，显示友好登录引导

### 登录用户

- 订阅资讯栏目和来源
- 收藏资讯并查看浏览历史
- 发布、评论和互动校园墙帖子
- 使用消息、好友和个人设置
- 持续使用 AI 助手并保存对话记录

### 管理员

- 从“我的 → 平台管理中心”进入管理功能
- 人工发布、编辑和删除官方资讯
- 运行自动采集器并查看采集状态
- 执行首次部署所需的数据表初始化

首页不提供管理员测试按钮或数据库维护入口。

## 自动采集与标准化

采集云函数位于 `cloudfunctions/crawler`，默认覆盖：

- 中央民族大学官网
- 中央民族大学教务处
- 中央民族大学新闻网
- 中央民族大学就业信息网
- 中国教育考试网·中小学教师资格考试

采集流程包括链接发现、正文提取、来源绑定、业务分类、校区识别、时间节点提取、内容哈希、去重更新和日志记录。采集结果写入官方 `contents` 集合，不会自动进入校园墙。

可通过云函数环境变量 `CRAWLER_SOURCES_JSON` 扩展学院、研究生院、团委、图书馆、后勤和其他权威来源。第三方密钥不得写入代码仓库。

详细说明见 [docs/crawler_integration.md](docs/crawler_integration.md)。

## AI 助手

AI 助手“奈雪”优先检索平台内已经标准化的校园资讯，并在需要时补充网络查询。涉及通知日期、报名截止、考试安排、招聘时效和政策信息时，必须以平台数据或权威来源为准；没有可靠依据时不得编造。

部署 `rag` 云函数时，需要在微信云开发控制台配置 `DEEPSEEK_API_KEY`，并选择 Node.js 18 或 20 运行时。`api` 与 `rag` 还必须配置相同的 `RAG_INTERNAL_TOKEN`，避免客户端绕过游客限制直接调用 RAG。`api` 与 `crawler` 需配置相同的 `CRAWLER_INTERNAL_TOKEN`，防止绕过管理员权限直接触发采集。多智能体编排说明见 [docs/ai_multi_agent_workflow.md](docs/ai_multi_agent_workflow.md)。

## 数据边界

- `contents`：官方或管理员发布的标准化校园资讯
- `sources`：信息来源及采集配置关联
- `tags`：订阅和内容标签
- `subscriptions`：用户订阅
- `favorites`、`history`：用户个性化数据
- `campus_posts`、`campus_comments`：校园墙内容
- `messages`、`friend_requests`、`friends`：社交关系与消息
- `ai_messages`：AI 对话记录与游客次数控制
- `crawl_logs`：采集任务运行记录

## 技术结构

- 微信小程序原生 WXML / WXSS / JavaScript
- 微信云开发数据库与云存储
- `cloudfunctions/api`：业务 API 路由
- `cloudfunctions/crawler`：多来源资讯采集与标准化
- `cloudfunctions/rag`：校园信息检索增强问答

## 部署提示

1. 在微信开发者工具中选择对应云环境。
2. 按 `rag → crawler → api` 顺序上传并部署云函数，均选择云端安装依赖。
3. 使用管理员账号进入平台管理中心，执行一次数据表检查与初始化。
4. 配置采集定时触发器和必要环境变量。
5. 重新编译小程序，分别验证游客、学生和管理员流程。

当前联调版本只在微信开发者工具中自动登录 `admin001`，真机和正式环境不会创建或
显示本地调试管理员。云函数的全局调试开关默认关闭；如需本地联调，应由开发者工具
上下文完成身份绑定，不要在生产环境配置调试登录环境变量。

当前产品名称统一使用“民大通 · 校园信息聚合平台”。
