# 从校园资讯到 AI 助手：我的个人小程序实践

> 以中央民族大学为真实场景，把分散在学校官网、学院通知、考试平台、竞赛页面和校园社区里的信息，整理成一个可信、可检索、能提醒下一步的校园入口。

![微信小程序校园信息聚合平台](images/robot.png)

## 一句话介绍

民大通不是一个“把网页搬进小程序”的资讯列表，而是一套面向学生日常决策的校园信息系统：先确认来源，再理解时间和对象，最后把通知转成可执行的行动。

教资只是“考试考证”中的一个业务。平台同时覆盖考研、四六级、三创赛、创新创业大赛、挑战杯、就业实习、学院教学、校园动态和二手书。

## 为什么需要它

校园里真正稀缺的不是信息，而是找到可靠信息的时间。一条考试安排可能藏在校外考试网站；一场竞赛可能只在某个栏目短暂出现；学院通知、学校通知和群聊转发又往往互相重复。

学生需要的不是更多链接，而是四个明确答案：

- 这条信息来自哪里？
- 它和谁有关？
- 什么时候截止或开始？
- 我现在应该做什么？

民大通围绕这四个问题设计，把“到处翻、反复问、害怕错过”变成“集中看、直接问、知道下一步”。

## 产品结构

```text
官方资讯层   官网、教务处、学院、考试平台、竞赛平台、就业平台
       ↓
标准化层     来源核验、正文清洗、分类、时间抽取、去重、时效评分
       ↓
智能服务层   RAG 检索、时间工具、联网查询、审核与反思、权限投影
       ↓
用户体验层   首页资讯、近期事项、AI 助手、校园墙、二手书、订阅提醒
```

官方资讯与学生内容保持边界：官方内容强调可信和可追溯，校园墙强调真实和互动，二手书使用独立规格字段描述交易信息。

## 当前版本的亮点

### 从信息聚合到事项理解

每条资讯尽量保留来源、发布时间、截止时间、地点、适用对象、行动项和原文链接。摘要不是简单截取文章开头，而是回答“谁需要关注、何时完成、下一步做什么”。

### AI 先路由，再回答

AI 助手先判断用户是在查通知、问时间、找竞赛、处理二手书、询问平台功能，还是提出私密请求；随后只调用该问题需要的工具。答案还会经过来源、时效、隐私和表达长度审核。

### 真实来源优先

内置来源包括中央民族大学及学院网站、教师资格考试、研究生招生、四六级、三创赛、中国国际大学生创新大赛、挑战杯和国家大学生就业服务平台。采集失败时显示失败，不使用虚构活动、旧年份或假链接填充页面。

### 面向学生的业务 Skill

- 教资、考研、四六级等考试节点识别；
- 三创赛、创新创业和挑战杯赛事追踪；
- 来源治理、去重、时效评分和证据评分；
- 校园 UI、AI 多智能体、时间读取和微信视频内容处理。

### 可控的个性化

平台可以逐步理解用户关注的学院、校区、考试和竞赛，但 AI 只接收完成问题所需的最小公开数据投影。个性化的目标是减少错过重要通知，而不是制造信息噪音。

## 功能一览

| 模块 | 作用 |
|---|---|
| 首页 | 分类浏览、关键词搜索、近期截止事项和官方来源标识 |
| AI 助手 | 多轮对话、历史会话、公开资讯检索和时间查询 |
| 校园动态 | 学生发帖、图片、标签、评论和互动 |
| 二手书 | 数量、新旧程度、位置、交易方式、原因和实物图 |
| 订阅 | 按栏目和来源关注信息 |
| 管理中心 | 分组运行考试、竞赛、学院和就业采集器 |
| 内容治理 | 去重、来源核验、时效筛选、演示数据清理和权限控制 |

## AI 工作流

项目使用 LangChain 节点和 LangGraph 状态图实现 STAR 工作流：

```text
S 识别情境       清理问题、识别风险、读取必要上下文
T 判断任务       识别意图、分类问题、选择工具
A 执行动作       查询公开数据、获取时间、联网检索、生成回答
R 返回结果       审核证据、时效、隐私和表达，必要时修订一次
```

工作流不开放用户密码、身份证、私信、收藏明细或管理员内部数据。游客可浏览公开内容并体验有限次数的 AI 对话；登录后才可使用订阅、收藏、发布和个人历史等功能。

## 真实采集与标准化

采集器位于 `cloudfunctions/crawler`，来源目录位于 `cloudfunctions/crawler/lib/source-catalog.js`。当前支持的业务分组包括：

```text
teacher-cert                 教师资格考试
graduate-exam                研究生招生与考研
exam                         四六级等考试
competition                  综合竞赛
three-innovation             三创赛
innovation-entrepreneurship  创新创业大赛
challenge-cup                挑战杯
career                       就业与实习
info-engineering             信息工程学院相关内容
```

标准化字段包括 `deadline`、`startTime`、`location`、`audience`、`actionItem`、`freshnessScore` 和 `evidenceScore`。只有抓取成功、通过学生相关性筛选并保留原文链接的内容才进入资讯库。

## 项目目录

```text

cloudfunctions/api             业务 API、认证和权限

```

## 快速开始

1. 使用微信开发者工具打开项目目录。
2. 在云开发环境中部署 `rag`、`crawler`、`api` 云函数，并分别安装依赖。
3. 只在云函数环境变量中配置模型、搜索和内部通信凭证，不把凭证写入小程序或 Git。
4. 进入“我的 → 平台管理中心”，初始化数据表并按分组运行采集器。
5. 使用游客、普通用户和管理员三种身份分别验证浏览、AI、发布和采集流程。

开发者工具联调阶段可自动绑定 `admin001`；真机和正式环境默认关闭调试管理员。

## 质量与安全

- 官方来源必须可访问、可追溯，失败时不伪造替代内容。
- AI 回答涉及现在、今天、截止时间时，使用服务器时间并标明时区。
- 数据库通过服务端公开投影供 AI 使用，客户端不能直接读取数据库。
- Token、API Key、媒体地址令牌、解密密钥、用户数据和视频缓存不进入公开仓库。
- 每次修改后运行 JavaScript 语法检查、RAG 测试、采集器目录测试和 Skill 校验。

## 演进路线

### 现在：可信资讯入口

完成来源采集、标准化摘要、AI 问答、校园墙、二手书和管理员分组运营。

### 下一步：校园事项引擎

识别报名、考试、比赛和活动的版本变化，提供“即将截止、与你相关、刚刚更新”三类入口，并支持用户确认后加入日历。

### 再下一步：个人校园记忆

根据订阅、学院、校区和时间偏好生成每周简报；当事项发生变化时，只提醒真正受影响的人。

### 更长期：可迁移的校园智能入口

将来源适配、字段标准、权限投影和审核规则抽象为配置，使同一套方法能够服务不同学校，而不复制任何学校的私有数据。

## 研究与致谢
